# 使用指南

## 基本流程

1. 在 Codex 任务中上传一个录音或含音轨的视频。
2. 用自然语言说明预计人数、主要语言、主题、专业领域和希望回答的问题。
3. Codex 从当前任务的附件信息取得真实路径，调用 Skill 包装器。
4. Skill 调用本地后端完成转录、说话人分离、清理和技术复核。
5. Skill 生成会议分析、主题时间轴和证据索引。
6. 在同一任务中继续提问，回答应带时间和匿名说话人标签。

用户不需要手动执行 PowerShell 来处理录音。

## 普通商谈

> 请使用会议录音分析 Skill 处理我上传的录音。预计 3 人，日语为主。请输出完整转录、重点摘要、决定、待办和时间轴。

未提供人数时，后端自动估计。未提供语言时使用 `auto` 与 `per-chunk`，每个长音频切块独立检测语言。

## 日英混合会议

> 请转录这个日英混合会议。不要给说话人猜姓名，保留匿名标签。请总结双方的主要观点，并列出每次语言和主题切换的大致时间。

## 光学研究会议

> 请使用会议录音分析 Skill 处理上传的录音。预计 4 人，英语和日语混合，主题是光学边缘检测，请加载 optical_edge_ml 术语表，并总结教授提出的修改意见。

只有领域或用户请求与光学、边缘检测、机器学习相关时，才加载项目术语表；普通商谈只使用通用清理规则。

## 指定初始问题

> 请处理上传的面试录音，预计 2 人，报告用中文。重点回答：候选人对项目风险的判断是什么？有哪些明确承诺？

Skill 不会把建议、假设或可能性写成正式决定，也不会在录音未说明时猜测负责人和期限。

## 继续问答

> 根据刚才的录音，关于 defocus 容许范围讨论了什么？请给出说话人和时间位置。

推荐证据形式：

```text
[00:12:34–00:13:08, SPEAKER_01]
```

回答应区分：

- 录音明确提到；
- 根据附近语境推断；
- 录音没有提供。

没有足够证据时应回答：

```text
录音中没有找到足以支持该结论的内容。
```

## 多个附件

用户应明确指出需要处理的文件。没有明确选择时，Skill 只能选择唯一明显的主录音；不得静默拼接多个附件。

## Resume

只有相同输入哈希和兼容配置才能恢复。对未完成 Job，用户应明确说“继续上次同名任务”或提供 `resume` 意图。输入或配置不同应使用新 Job 名称，不能覆盖旧结果。

## 结果可信度

- `critical` 复核项必须在最终回复中披露；
- `warning` 可继续分析，但相关片段需标注不确定性；
- 清理失败时可回退到原始 ASR 文本，并明确说明；
- 转录失败且没有安全可用的完整结果时，不生成看似成功的摘要；
- 匿名说话人标签只表示本次录音中的聚类，不代表真实身份。

## 常见问题

### 找不到后端

检查安装目录的 `local_backend.json` 或 `VTT_PLUS_*` 环境变量。错误会在模型加载前列出缺失组件。

### Hugging Face 授权失败

在本机后端环境中恢复授权，不要把令牌贴进对话、配置仓库或日志。

### CUDA 显存不足

保留失败 Job 和日志，释放显存后使用兼容配置 Resume。不要删除已完成的 chunks。

### 路径包含空格或日文

安装器与运行器均使用独立参数和 `pathlib.Path`。不要手工拼接 shell 命令。

### 分析失败但转录成功

保留转录文件，只重跑分析层，不重新运行 ASR、Forced Aligner 或 pyannote。
